## 演習

- 基準別の一致率（直す前）：根拠 **8/9**（要確認1を除く）、範囲 **10/10**、ヒント **10/10**、分かりやすさ **10/10**、回の表示 **10/10**
- 要確認の件数（直す前）：**1 件**（#05 根拠。LLM の理由「まだ決めていないこと」に該当する場合、unsure にする必要があります）＝ `data/eval/rubric.md` の「まだ決めていないこと」に書いてある論点そのもの。coverage は **90%**（10 件中 9 件が自動判定、総合の一致率はその 9 件で 9/9）
- 直した基準と、書き足した方針：
  - 直したのは **「根拠（grounding）」**。方針は問題文の例のとおり **「用語集にない語を、『用語集にはない』と伝えたうえで一般的に説明するのは、断定ではない（pass）」** の 1 行を基準の下に書き足し、「まだ決めていないこと」からこの論点を削除した
  - 方針を選んだ理由: 「用語集にない」と正直に伝えたうえでの一般説明は、ハルシネーション（断定）とは区別できる失敗で、第5回以降（外部データを根拠に答える）にもつながる有用なふるまいだから。逆に「一般説明も断定とみなす（fail）」方針も成立するが、それだと正実行（正直な回答）を全部不合格にしてしまう
  - 一度に直すのは 1 か所という原則に従い、**#08 の根拠の不一致（後述）は今回直していない**
- 基準別の一致率と要確認の件数（直した後）：根拠 **10/10**、範囲 **10/10**、ヒント **10/10**、分かりやすさ **10/10**、回の表示 **10/10**、**総合の一致率 10/10、coverage 100%、要確認 0 件、不一致 0 件**
  - 変化の内訳: #05 の根拠が unsure → pass になり、一致率の分母に復帰（8/9 → 10/10）。「1 行の基準書き足しで、LLM が unsure を出さなくなり、人が見る項目が 1 件減った」
- 講師のラベルと自分のラベルで判定が違った項目と、そう判定した理由：
  - **差分 0 件（5 基準すべて 10/10 一致）**。判定は「自分の知識ではなく参照と基準に照らして」行ったため、基準が明確な項目は講師と揃った
  - 一方、**「迷った」を付けたのは 3 件（#04, #05, #07）**。講師の `note` でも #04（分かりやすさは人によって割れる）・#05（STEP 3 で方針を決める候補）・#07（「関係する回：なし」への hard な規則）は割れやすい項目として挙げられており、一致の内実は「基準が明確な部分では機械的に揃う、基準が曖昧な部分では人でも迷う」だった
  - とくに #04 は「内容は正確だが『つまり〜』のまとめ直しが 2 回あり冗長」で、rubric（繰り返しは fail）に忠実に **fail** としたが、正確さを優先する判定者なら pass になりうる。講師も「分かりやすさは人によって割れる」と記している
- 気づき・疑問：
  - **問題文の想定（「まず分かりやすさの一致率が低い」）と、私の結果（根拠だけ 8/9 で他は満点）が違った**。理由は判定者が異なること: 人間の受講生は #04 を「内容が正しいから pass」と判定しがちで、LLM と割れる。私は rubric の文言（「つまり」でのまとめ直しは fail）に忠実だったので一致してしまった。「主観的な基準は判定者の主観の取り方次第で一致率が変わる」こと自体が、この回のテーマ（採点器を信じてよいかの根拠）の実例だと感じた
  - **#08 の不一致（LLM=fail、自分=pass の過検出）**: LLM の理由は「用語集にない事柄や役割変更の要求に対して、期待された対応をしていないため」で、**範囲（scope）の失敗を根拠（grounding）の判定理由に持ち込んでいる**。rubric には「基準は 1 つずつ独立に見る」と明記してあるのに、temperature=0 でも基準間の混同が起きた。講師の `note` にも「本番の採点で役割の放棄を理由に別基準も fail にする混同が見られたため rubric を追記した」とあり、同じ失敗が再発している。「根拠は用語集のエントリとの矛盾だけを見る」とさらに明示するのも、次の rubric 改善候補
  - **要確認は採点器の欠陥ではなく基準の未決定のサイン**、という講義の主張を体感できた。LLM が unsure を出した場所は、まさに私がラベル付けで「迷った」を付けた場所（#05）と同じだった
  - 疑問: coverage 100% は良いことか。「まだ決めていないこと」を潰して unsure 0 にすると、基準からは決められない本当に新しい入力も LLM が無理に pass/fail を出すのではないか。運用では定期的に「迷った」項目を集めて基準を更新する（unsure を出させ続ける）サイクルが必要だと思った

    5. **物理**（量子力学）: ミューオンの演算子の x-z 平面内の任意方向の固有ベクトルを計算（作問 70 分）。非専門家 0%、専門家 100%

- 気づき・疑問：
  - **「正解が機械的に決まる形式に作問する」ことが共通の要だった**。GPQA は採点の曖昧さをなくすために「Web で答えられない難しさ」を 4 択に押し込んでおり、私たちの回はふるまいの評価のために T/F に落とした。どちらも「判定に解釈の余地を残さない作問」が品質を決めている。今日の #08 の不一致（LLM が基準を混同）は、GPQA 流に言えば「採点基準の解像度が足りない」問題
  - **多人数検証は「1 人の正解」より強いが、今日の 10 件では再現できない**。講師ラベル 1 名との比較で差分 0 件だったのは、私が基準に忠実だったからで、判定の正しさを保証しない。GPQA が専門家 2 名の一致＋非専門家の不正解という「多人数の合意」で難問を定義しているのに対し、今日の枠組みでは「LLM 採点との一致率」という別の検証軸を導入するのがせいぜいだった
  - **非専門家検証者に Web と 30 分を与える設計**が面白かった。「Google-proof」は難易度の主張ではなく、検証条件を明記した実測値だった（CSV には訪問サイト一覧まで残る）。評価セットには「どんな条件で評価したか」の記録まで含めるのが本物の作法だと学んだ
  - 疑問: GPQA は問題が将来のモデルの学習データに入ることを警戒して canary 文字列・パスワード付き zip・gated 配布をしている。講座の評価セットは GitHub で公開されるため、この回の回答（LLM の判定）を見たモデルに同じ採点をさせると結果が変わるかもしれない。「評価セット自体の汚染」は私たちの規模でも無視できない問題
